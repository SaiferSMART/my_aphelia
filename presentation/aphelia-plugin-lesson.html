Aphelia Введение 1 / 32

Занятие

Как мы собирали плагин для Reels — и почему остались на Remotion

Это не абстрактный обзор «лучших библиотек». Это реальный путь проекта Framepro → Aphelia: с чего начинали, что пробовали, что выкинули и что работает в продакшене сегодня.

Задача

Что мы строили

Автоматический конвейер: из ссылки, новости или темы — вертикальный ролик 60–90 секунд на русском. Озвучка, стикмены, субтитры, музыка без страйков, монтаж под голос — и всё это через Cursor-плагин с субагентами, а не ручной монтаж.

Референсом служили два шортса про «YouTube-урок → навык для Claude»: карточки, крупная типографика, чеклисты, сравнение двух колонок, быстрые свайпы между сценами.

Важный факт

Референсы сами сделаны в Remotion

В метаданных обоих MP4 стоит Made with Remotion 4.0.506. То есть визуальный язык, который мы копировали, изначально родился в React-композиции, а не в HTML-странице.

Это не значит, что Remotion был очевидным выбором с первого дня — мы всё равно начали с другого движка. Но референс подсказал, куда в итоге придётся прийти.

С чего начали

Первый движок — HyperFrames

HyperFrames (HeyGen, Apache 2.0) — рендер видео из HTML. Композиция — это index.html: слои с атрибутами data-start и data-duration, анимации через GSAP. CLI hyperframes render снимает кадры и собирает MP4.

Почему он казался удобным для агента: не нужен React — агент генерирует HTML и таймлайн GSAP. Лицензия без порога «плати от N сотрудников». Skills для HyperFrames уже стояли в окружении.

Параллельно

Второй движок — Remotion

Remotion — React + TypeScript. Кадр = компонент, время = useCurrentFrame(), рендер = headless Chromium по кадрам + FFmpeg. Официальные пакеты: переходы, субтитры, шрифты, фигуры, waveform.

Мы подняли шаблон templates/remotion/ и научили его читать тот же storyboard.json, что и HyperFrames. Скрипт timeline.py до сих пор в комментарии называется «источник правды для обоих рендереров» — след той эпохи.

Период v1

Два рендера из одного storyboard

storyboard.json
  → edge-tts + тайминги слов
  → compose.py → index.html (GSAP) → hyperframes render
  → sync_remotion.py → data.ts → npx remotion render

Проект openai-hf-reel/ и папка pipeline/ — это как раз HyperFrames-ветка. Один бриф, два MP4: можно было сравнить качество и скорость разработки.

Почему ушли

Почему HyperFrames убрали из продакшена

  • Два движка = двойная поддержка. Каждый новый эффект (караоке, wipe, waveform, камера) приходилось чинить и в GSAP, и в Remotion.
  • Референс и экосистема — на стороне Remotion. Переходы, TikTok-субтитры, fitText, motion blur — уже готовые пакеты, а не ручной GSAP.
  • Агент перестал писать HTML. Стабильнее отдавать JSON-схему (storyboard.json) и один проверенный рендерер.
  • Баги GSAP в проде: стикер «пропадал» без autoAlpha: 1 в конце анимации; свои кривые easing пришлось дублировать в Remotion (ease.ts — «как HyperFrames»).
  • Упрощение репозитория. При переименовании в Aphelia (коммит e7ca36d) оставили «только то, что нужно для запуска» — HyperFrames, pipeline и docs ушли из git.

Почему остались

Почему Remotion — единственный движок сейчас

Один render.py: timeline → музыка → sync_remotion → npx remotion render → ffmpeg loudnorm. Агент-сторибордер выбирает эффекты из каталога remotion-capabilities.md — push, wipe, iris, flash, karaoke, waveform, custom-слои.

Если эффекта нет в каталоге — пишется custom/MyEffect.tsx, TypeScript проверяет типы до рендера. Это предсказуемее, чем генерировать сотни строк GSAP на каждый ролик.

Голос v1

С чего начинали озвучку — Edge TTS

Первый прогон: edge-tts, голос ru-RU-DmitryNeural. Бесплатно, быстро, word boundaries для привязки сцен к словам.

Минусы, из-за которых ушли: «роботный» тембр; нельзя зафиксировать фирменный голос бренда на все ролики; клон Edge-копии тянет и роботность источника. Для explainer-канала с узнаваемым диктором этого мало.

Голос сейчас

Qwen3-TTS — продакшен

VoiceDesign (один раз)

Текстовое описание диктора → 6 дублей → лучший ref.wav в voices/narrator-ru/

Base (каждый ролик)

Клон по 3-секундному референсу. Каждое предложение отдельно, проверка Whisper, до 3 дублей.

Выход: vo.mp3, vo-words.json — основа монтажа по словам (at_word в storyboard).

Что пробовали

Silero v5, F5-TTS Russian, CosyVoice 3

На одном и том же сценарии (run dreamx-creator) прогнали бенчмарк: ~10 голосов Silero, F5-TTS, CosyVoice — скрипт voice_bench.py, отдельное venv Python 3.10 в vendor/tts-extra.

Итог: оставили один движок — Qwen3-TTS 12Hz-1.7B. Остальное сняли из продакшена: лишний зоопарк, тяжёлый setup (CosyVoice/F5), нет связки VoiceDesign + клон + проверка Whisper в одном пайплайне.

Ударения

ruaccent и политика «чистый дубль первым»

Qwen не русская TTS — ударения и заимствования ломает. Подключили библиотеку ruaccent (turbo3.1 + словарь омографов). Слова из qwen_force_marks и ruaccent_custom_dict — в словаре плагина.

Важный вывод после замеров: метки ударения U+0301 в ~⅓ случаев дают глайд («Алибоюбы»). Поэтому сначала чистый дубль без меток; маркированный принимается только если Whisper слышит слово идеально (sim ≥ 0.97).

Музыка

От Mixkit к ACE-Step

Сначала — библиотечные треки Mixkit (6 BGM в templates/audio/bgm/). Риск: один и тот же трек на двух роликах, возможные совпадения с Content ID.

Сейчас по умолчанию: ACE-Step 1.5 (MIT, коммерция OK) — уникальный инструментал под music-brief.json (жанр, bpm, настроение ролика). Mixkit — только fallback, если нет GPU или uv.

SFX

186 звуков и video-shotcraft

Каталог sfx-catalog.json — whoosh, удары, клавиатура, часы, стекло… Сторибордер подбирает 8–12 звуков по смыслу слов сценария, один звук — не чаще 3 раз за ролик.

Идеи звукового дизайна и ритма переходов частично переняли из репозитория video-shotcraft (рецепты кадров, BGM, SFX) — не кодом, а правилами в motion-library.md.

Картинки

Стикмены: GenerateImage + rembg

Каждый ролик — новые PNG по _style-reference.png (Cursor GenerateImage). Не копируем старые стикеры из библиотеки.

rembg + маска «чернил» в cutout.py: rembg съедает тонкие линии, маска по чёрному контуру их сохраняет. В storyboard только assets/cut/*.png с альфой.

Скринкасты

Playwright + ffmpeg

Для сцен «доказательство» — запись прокрутки страницы-источника: Playwright пишет webm, ffmpeg режет белый экран в начале, кодирует H.264 30 fps с keyframes — чтобы Remotion мог точно seek.

Комментарий в capture_web.py до сих пор говорит «для обоих рендереров» — ещё один след HyperFrames-эпохи.

Контракт

storyboard.json — мост между агентом и пикселями

Агент не пишет React на каждый ролик. Он заполняет JSON: сцены, слои, at_word, переходы, камера, стиль-пресет, музыка. validate_storyboard.py и timeline.py проверяют и собирают timeline.json → sync_remotion.py → рендер.

6 стиль-пресетов (lime, orange, cyan, pink, yellow, violet) — чтобы ролики не выглядели одинаково; валидатор ловит повтор пресета с прошлого run.

LLM

Gemini 3.7 для текстов

Research, сценарий, заголовки и описание — Gemini 3.7 (gemini-3.7-flash-high) через Task. Не Composer и не Grok для этих ролей — явный slug в оркестраторе.

Сценарий: 140–215 слов, числа словами, бренды на экране кириллицей, в микрофон — латиницей (GitHub, Qwen) — иначе Qwen читает «Гитхаб» как русское слово.

Плагин

Cursor Plugin — не только скрипты

rules/ — оркестратор: волны Task, что параллельно. agents/ + skills/ — 10 ролей. commands/ — /aphelia-new, /aphelia-render, /aphelia-voice.

Директор в чате сам не рендерит и не пишет сценарий — только координирует субагентов. Память прогона: aphelia-memory/runs/<slug>/.

Волны

Порядок работы агентов

researcher → writer (Gemini)
  → voice ‖ illustrator×2–3 ‖ screencaster
  → storyboarder (стиль, музыка, SFX, эффекты)
  → renderer (ACE-Step + Remotion)
  → guardian ‖ publisher (Gemini)
  → fixic (если были инциденты)

Параллель на волне 3 и 6 экономит 2–3× времени. Storyboarder идёт после voice — нужны тайминги слов Whisper.

Утилиты

ffmpeg, Whisper, Python, Node

  • Whisper — проверка озвучки + word timestamps для монтажа
  • ffmpeg — loudnorm −14 LUFS, скринкасты, QA-кадры, не замена Remotion
  • Python 3.12+ — voice, timeline, render, qa, cutout, music
  • Node 20+ — Remotion CLI, Playwright в scripts/node
  • uv — изолированное окружение ACE-Step в vendor/ace-step
  • GPU ≥ 12 ГБ — Qwen3-TTS 1.7B и ACE-Step turbo

Что ещё можно добавить

Библиотеки, которые мы смотрели, но не встроили

  • @remotion/three — 3D-сцены в кадре (пакет есть в экосистеме, в Aphelia пока нет)
  • remotion-captioneer — больше готовых стилей субтитров, чем @remotion/captions
  • ElevenLabs / Kokoro — в чужих пайплайнах; у HyperFrames TTS без русского
  • HyperFrames capture — автоматические скрины сайтов в композицию (мы сделали Playwright отдельно)
  • Lottie-файлы — слой lottie в storyboard уже есть, каталог ассетов можно расширить
  • Remotion Lambda — облачный рендер, если локальный GPU не тянет
  • Silero / F5 / CosyVoice — вернуть как опцию в voice_bench, не в прод

Добавлять имеет смысл только то, что закрывает дыру: новый эффект → сначала каталог Remotion, потом custom.tsx, HyperFrames — только если снова нужен HTML-first без React.

Главное

Три вывода для занятия

  1. Сначала был HyperFrames (HTML+GSAP), сейчас только Remotion — не потому что HyperFrames «плохой», а потому что один движок с официальными пакетами и JSON-контрактом дешевле в поддержке.
  2. Референс уже был Remotion — мы долго копировали его через GSAP, потом перестали дублировать.
  3. Плагин = оркестратор + контракты + проверенные библиотеки — агенты пишут JSON и тексты, тяжёлое (TTS, рендер, QA) делает код.
